# Changelog

## 3.1.1 (2026-10-21)
- **Fix: subscription CLI seats no longer hang when the CLI is installed through a version manager.** `cli_env` stripped every variable outside a small allowlist, including the `MISE_*`/`__MISE_*`, `ASDF_*`, `VOLTA_*`, `NVM_*`, `PYENV_*`, `RBENV_*` and `FNM_*` variables that mise/asdf/volta/nvm/pyenv/rbenv/fnm shims and wrapper scripts need to resolve the real binary. A shimmed `claude`/`codex`/`gemini` re-resolved (or hung) instead of running, so `maestro-router serve` sat silent until the 300 s CLI timeout while the same CLI answered in seconds from a shell. Launcher variables now pass through for every CLI seat; other providers' keys and `MAESTRO_*` are still dropped. Found by a live serve run against a mise-wrapped Claude Code; regression test covers the keep/drop split.
- The public repository `this-live/maestro-router` and the v3.1.1 release (wheel + tag) are the pinned install source; the private development history is never pushed there (`scripts/check-history.sh`).

### Maestro S1

S1, Maestro's own tiny decision model, and expected-utility routing, behind a flag (`decider: utility`; the default stays `ladder`, with S1 in shadow mode). Design: `docs/S1-SPEC.md` and docs/DESIGN.md "v3 Stage 3".

- **S1** (`s1.py`, `data/s1.bin`, 1.2 MB, stdlib): task text to a posterior (job, difficulty with uncertainty, tools, self-contained, stakes, detectable, ambiguity, output tokens, agent turns, unfamiliarity) through crc32 features, a Bloom known-feature filter and an int8 embedding bag; about 0.2 ms on a short prompt. The bootstrap weights are trained on `evals/train.jsonl` only and do not yet replace Naive Bayes for `classifier: auto`; `--classifier s1` uses them.
- **Expected-utility decisions** (`decide.py`, `data/decide.json`): every seat gets a success probability and an expected utility in dollars (value of success, API dollars, a quota price that is zero while a subscription window has slack and rises with its forecast burn, waiting time, the cost of a failure). The calling agent is a seat (`--current-tier`), a conversation stays on its model when switching would lose the cache, `private` keeps tasks on local models, and the decision reports `options`, `p_success`, `escalate_to`, `confidence` and a `decision_id`. Tool jobs in skill mode stay on the ladder until the release gate.
- **`maestro-router route`** gains `--decider`, hint flags (`--job`, `--tools`, `--self-contained`, `--size`, `--stakes`, `--context-tokens`), `--classifier s1`, an options table under `--explain`, and appends `~/.maestro/decisions.jsonl` (heads, options, a MinHash; never text). New commands: `s1`, `decide`, `outcome`, `feedback`, `learn`, `install --hooks` (the Claude Code SubagentStop hook that records test results of delegated work).
- **Proxy**: utility planning over the same hard-filtered candidates, shadow decisions, affinity on every turn with a switching cost, `decision_id`, `p_success` and `escalate_to` in `x-maestro-decision`, outcome signals (feedback API and header, test results in tool messages, implicit signals logged at weight 0), `POST /v1/systemone` (TypeSafe Jev's typed-decision format, answered natively or by a model you serve), `GET /api/alpha`, a daily personalization refit, new `decisions` columns and an `outcomes` table.
- **Personalization** (`learn.py`): a guarded, replayed fit of per-seat offsets, per-job difficulty shifts and a calibration from your outcomes into `~/.maestro/personal.json`; `learn --reset` deletes it.
- **Quota history**: the statusline script logs Claude's window percentages to `claude_limits.log` and `quota` keeps Codex samples in `quota_hist.json`, for the burn-rate forecast; `quota.window_view`.
- **Discovery** writes each model's ability per job (`theta`, with the link's hash), `catalog_sha`, the blended score axes, and with `--live` the systemone strategy of loaded local models.
- **Web UI**: a Decider setting and private mode, a shadow-agreement card, Good / Bad buttons in Activity, and the options table in Try it.
- **Evals**: `split.py`, `label.py`, `alpha.py` (pilot, alpha set, replay, CI and release gates, pacing simulation), `fit_link.py`, `train_s1.py`, `typed_eval.py`, `run.py --classifier s1`; CI runs `split.py --check` and `alpha.py gate`.
- The Naive Bayes and Jev code moved to `nb.py` and `jev.py` (`router` re-exports the same names); `router.split_material` is a `str.find` loop instead of a `re.S` regex.
- **Website** (`site/`, deployed on Railway at https://maestro.this.live): a landing page, docs, privacy and terms for the free, open-source, local-first router, in the original Maestro brand (navy and cyan, the robot logo, sparkles). `site/serve.py` is a stdlib static server (`/health`, security headers and a CSP with no inline script, caching, gzip, ETags, no directory listing, traversal-safe) that also serves `/demo/`: the shipped web UI with a small fetch shim that answers its `/api/*` GETs from recorded sample data (`site/demo/api/*.json`, regenerated by `site/make_demo.py` from a real `maestro-router serve` over fake providers) and refuses every write. `railway.toml`, `site/Dockerfile` (python:3.12-slim, non-root) and `.dockerignore`; `tests/test_site.py`. The site sets no cookies, runs no analytics and loads nothing from other origins.
- **Web UI restyle**: the dashboard uses the same navy and cyan palette, the robot mark in the header and favicon (inline, no external requests) and a light variant; no behaviour or element ids changed.
- **Ladder retuned on measured outcomes.** On 100 checker-graded self-contained pilot tasks, Sonnet-class models solved 97-100% of the hard (d2) and very hard (d3) items (haiku 82% overall, opus 99%, fable 100%). Hard work now goes to `standard` for every job except `plan` (`strong`); very hard work goes to `strong` (`frontier` only for `plan`); `review` and `debug` are `standard` at d0 to d2; `ask` d3 is `standard`. On the pilot tasks the old table sent 77% to `strong` at an average price of 4.16 (haiku 1, sonnet 2, opus 4, fable 10) for 99 of 100 solved; the new one costs 2.26 for 98 of 99 gradable (one answer was excluded because the model used a tool). Rules eval, test half: category accuracy 53.2% -> 65.0%, within one 93.7% -> 99.6%, under-routed 8.9% -> 8.0% (CI floors and the README table updated). Override per job with `ladder` in the config. DESIGN.md deviation 133.
- **Tests no longer depend on the host.** The suite never probes this machine's real model servers (Ollama, vLLM, ... on the built-in localhost ports; new opt-in `MAESTRO_NO_BUILTIN_PORTS`, production default unchanged), the fake upstream's listen backlog fits the 40-request burst test on macOS, and the CLI client's "not on PATH" test ignores a real `codex` in `/usr/bin`. DESIGN.md deviation 137.
- **Arena** (`evals/arena.py`, `evals/arena/`, `docs/ARENA-RUNBOOK.md`, Claude Code skill `.claude/skills/arena/`): runs the same tasks through your harnesses and models and ranks them. Harnesses are Claude Code, Codex, Gemini CLI, OpenCode and Hermes; models include API seats and served local models, chat or through OpenCode / Hermes.
  - Suites: checker-graded verifiable items, agentic fixtures in a temp git copy with hidden tests (escapes flagged), and open prompts judged blind by a multi-family panel (criteria first, both orders, Bradley-Terry with bootstrap intervals, position, length and self-preference checks).
  - `seats`, `run` (concurrency, quota-aware, budget cap, resumable, `--dry-run`), `report` (leaderboard, value frontier, routing replay against always-X and hindsight, markdown and self-contained HTML) and `export` (alpha outcome rows for S1).
  - All argv lives in one table. Claude Code's flags were checked against its `--help` and a live run; the other harnesses' rows follow their docs and are marked as assumed. DESIGN.md deviation 135.
  - Fixes from the first run on a second machine (codex 0.160.1, opencode 2.0.20, hermes 0.21.3, all run live against a served vLLM model): Hermes runs with `-Q`, because plain `hermes chat -q` prints a banner, a boxed answer and resume hints that were graded as the answer; OpenCode runs with `--standalone`, because `opencode run` otherwise starts a shared background service that outlives the cell and keeps the first cell's config, so later seats could reach the wrong provider. The Codex, Gemini CLI, OpenCode and Hermes rows record what was verified. The runbook covers Codex's misleading "not supported when using Codex with a ChatGPT account" (an old CLI) and Gemini's `IneligibleTierError` (a refused login).
  - Agentic containment: every CLI now runs with `PWD` set to its cell's work tree. OpenCode 2.x works in `$PWD`, not its real cwd, so it inherited the directory the arena was started from and edited the real fixture in the repository instead of its copy. Cells on the same fixture no longer overlap, so a change to a fixture is blamed on the one cell that made it (it used to fail every cell running at the time).
  - Claude Code runs with `--safe-mode`: on a customized install the user's plugins, skills, hooks and MCP servers made a one-line prompt ~390k tokens and every cell failed.
  - Version-dependent flags: a row item `("if", [subcommand], [flags])` adds the flags only when `<cli> <subcommand> --help` lists them (read once per executable). `--safe-mode` (Claude Code 2.1.104 lacks it) and OpenCode's `--standalone` (the 1.18.x release line rejects it and runs no shared service) use it.

## 3.0.0

The proxy qualifies candidates as `score.pick` does (job strength and the model's own tier must reach the cell), reads `models.json` through `catalog.load_models`, and runs discovery from the UI.

- **Maestro uses what you already serve; it never downloads, loads or starts a model.** Ollama's `/api/ps` and LM Studio's model state tell installed from loaded models (GET only); a model that is installed but not loaded is listed but never routed to (skill `route`, the proxy, `discover --live`), `maestro run` refuses it unless `--allow-load`, and the proxy answers a request for it with 409. The config key `local_allow_load` (default `false`) lifts this, at the risk of exhausting memory. `models.json` has `loaded` and `routable` per local model. Model suggestions appear only when nothing is served: plain `discover` prints "serving N models - using these" or "nothing served" per box, `--local-fit` on a box that serves models says the suggestions would replace what it serves (one model server usually claims most of the memory) and marks each command "stop the current server first", `setup` prints each box's hardware and what it serves, and the UI's "Could run locally" panel shows "Using: ..." with the alternatives folded away.
- **Fixes from end-to-end testing.**
  - Providers that share a key variable (`MINIMAX_API_KEY` -> minimax, minimax-cn, the coding plans; Zhipu, StepFun, Xiaomi, ...) count once: the one named under config `providers`, else the primary. `GITHUB_TOKEN`, `GITLAB_TOKEN`, `HF_TOKEN`, `AWS_*` and Vertex settings no longer make `github-copilot`, `gitlab`, `huggingface`, `amazon-bedrock` or `google-vertex*` "connected"; name them under `providers` to use them.
  - The proxy skips API models priced 0 and `:free` ids (as `score.pick` does) unless requested by id or pinned.
  - Fallback tries other providers first: after a failure it skips the failed provider's remaining models, and 401/403 (10 min), 0 and 5xx now put the whole provider on cooldown.
  - `prefer_local: false` no longer routes `maestro/auto` to local models through the ladder's local cell.
  - A truncated upstream stream ends with an `error` event and `[DONE]`; the listen backlog is 128; `serve` flushes its banner; `maestro models --json | head` no longer prints a traceback.
  - Dated snapshot ids (`claude-haiku-4-5-20251001`) score like their benchmarked base; `developer` messages become `system` for non-OpenAI hosts; the skill router rates local models by their `discover` score in models.json.
- **`maestro serve`: an OpenAI-compatible router and web UI (v3, stage 2b).** `maestro/server.py` serves `/v1/models` and `/v1/chat/completions` (streaming, tool calls, images, `stream_options`) on `127.0.0.1:4545`. `maestro/auto` classifies the request; `maestro/<category>`, `maestro/<job>` and `<provider>/<model>` narrow or fix the choice. Candidates are filtered (tools, vision, context, quota, `max_tier`), must reach the category's job-strength floor, and are ranked by cost, quota headroom and latency. Tool turns stay on the conversation's model, a failure before the first byte falls back (three tries), and every request is a row in `~/.maestro/maestro.db`. `--host 0.0.0.0` requires `MAESTRO_API_KEY`; the admin API needs the token in `~/.maestro/admin_token` and same-origin requests. Quota is refreshed every 10 minutes.
- **Web UI** (`maestro/ui/index.html`, one file, no external requests): Overview, Providers (write-only keys, quota bars), Models (category pins, enable/disable), Routing (ladder editor), Activity and Try it, plus a "Could run locally" panel.
- **`maestro hermes --print|--install`** prints (or safely appends) the Hermes Agent custom-provider config; **`maestro setup [--yes] [--endpoint URL]`** is the interactive quick start, and asks for model servers on your network (a DGX Spark running vLLM, an Ollama box), probes them and saves them to `local_endpoints`.
- New config keys: `models_overrides`, `log_prompts`, `session_affinity_header`, `allowed_origins`.
- **Discovery (v3, stage 2a).** `maestro discover` detects every usable model (API keys, subscription CLIs, local and network servers), joins it to a bundled models.dev snapshot (`data/catalog.json.gz`, 381 text models from every lab with their benchmarks, 7,760 provider entries, 125 KB, rebuilt by `evals/build_catalog.py`) and scores it: benchmark percentiles among recent models blended with a prior from size, price, name and age (capped at 0.40 past 18 months), damped for models with few benchmarks and for labs that report on fewer than three models, then a strength per job and a category (`frontier`, `strong`, `standard`, `fast`, `specialist`, and `local` with a `serves` tier). It writes `~/.maestro/models.json` (contract in docs/DESIGN.md; `catalog.load_models()` applies `models_overrides` from the config, which survive rediscovery) and prints a table by provider. `maestro models` shows the map once it exists (`--seats` for the old per-harness table).
- `discover --refresh-catalog` merges the live models.dev API and falls back to the snapshot offline; `--backtest` routes the eval prompts over your map (category hit rate, cost per 100 requests against always using the strongest model, local share); `--live N` measures latency and failures with tiny prompts.
- **Local fit is throughput-aware.** Each fit gets an estimated decode speed (`memory bandwidth x 0.6 / (active parameters x bytes per parameter)`, bandwidth from a device table or `local_endpoints[].hardware.bandwidth_gbps`) and the ranking multiplies the score by 0.3 under 10 tok/s and 0.7 under 25, so a dense 128B model on a DGX Spark no longer beats a fast mixture-of-experts model. Rows in `models.json` carry `tps`, `tps_est` and `active_params_b`. gpt-oss is served as released (MXFP4).
- **Benchmark gap-fill.** `evals/extra_benchmarks.json` holds 630 rows (50 models) read from official model cards (gpt-oss, Qwen3-Next / 3.5 / 3.6, GLM-4.6 / 4.7, MiniMax M2 to M2.7, Gemma 4, DeepSeek V3.1 / V3.2 / V4-Flash, Kimi K2.5, Step 3.5 Flash, Nemotron 3, Inkling, Nex-N2-Pro, ...), each with its source URL; `build_catalog.py` merges them.
- **`score.pick`**: one function ranks a discovered map for a job and ladder cell (job strength and tier at the cell's level, cost, quota headroom, `prefer_local`, objective) and returns reasons; the backtest uses it. Under-routing on the eval prompts fell from 17.9% to 8.9%.
- **Open-weight registry and local fit.** Every open-weight model in the snapshot has its Hugging Face repo and parameter counts (from the Hub, else a verified table, else the name; unknown stays unknown). Local models join the catalog by Hugging Face repo (quantization suffixes ignored) or Ollama tag and get real scores. `discover --local-fit` lists, per box (this machine, or `local_endpoints[].hardware`; a "spark" endpoint is assumed to be a 128 GB DGX Spark), the best open-weight models that fit at BF16, FP8, NVFP4 or Q4 with a `vllm serve` / `ollama run` command, and how the models it already serves rank. Advice only.
- **Providers, clients and quota (v3, stage 1).** `maestro/providers.py` knows every provider in models.dev (225, from `data/providers.json`, regenerated by `evals/build_providers.py`): env vars, base URL, wire style (`openai`, `anthropic` or `unsupported`) and per-model overrides. Detection is presence-only (an env var, `~/.maestro/keys.env`, a subscription login file, the macOS keychain item without reading it); `maestro keys set|unset|list` manages `keys.env` (mode 0600, hidden prompt, values never shown); `maestro detect` shows a compact providers section and `detect --models` lists each provider's models live (8 s timeout) and saves `~/.maestro/providers.json`. OpenAI-compatible local servers keep raw model ids and `max_model_len`.
- `maestro/clients.py`: `complete(provider, model, request, stream)` for OpenAI-compatible providers (streaming relay, `reasoning_effort` retry), Anthropic (OpenAI chat translated to Messages and back, streaming included) and subscription CLIs (chat only, never with tools or images), all returning OpenAI chat.completions shapes.
- `maestro/quota.py`: rate-limit header parsers (OpenAI, Groq, Cerebras, Anthropic, `retry-after`), cooldowns after 429/5xx persisted in `~/.maestro/quota.json`, OpenRouter and DeepSeek probes, Codex rollout limits and Claude Code limits. `maestro install --statusline` writes `~/.maestro/statusline.sh` and prints the `settings.json` snippet for Claude Code's statusLine; it edits nothing.
- **The router is now a package** (`skills/maestro/scripts/maestro/`, no behavior change). `maestro.py` became `maestro/router.py`, `maestro_model.json` moved next to it, `import maestro` still exposes the same API, and the CLI is `python3 skills/maestro/scripts/maestro <cmd>` (also `python -m maestro`). `local` delegate argv now points at the package directory. The wheel ships `maestro_model.json` as package data.
- **One configurable model map per harness, with dated suggestions.** Routing used to pick only Claude models unless you wrote `harness_models`. Now every harness has a model for `fast`, `standard`, `strong` and `frontier` out of the box: Claude Code `haiku/sonnet/opus/fable`, Codex `gpt-6-luna/gpt-6.1-sol/gpt-6.1-sol (effort high)/gpt-6-astra`, Gemini CLI `gemini-flash-lite-latest/gemini-flash-latest/gemini-3.1-pro-preview` (twice), and OpenCode `provider/model` ids for the first of anthropic, openai, google you have a key for. The ids are a snapshot of models.dev as of 2026-09-30. A cell can be an id or `{"model", "effort"}` (effort is passed to Codex as `-c model_reasoning_effort=`, ignored elsewhere). `models` in the config replaces `harness_models`, which still works but is deprecated. `models.local` pins which local or network model serves which category.
- **`maestro models`** shows the effective map (category, model, where it came from, whether it is available) and the harness Maestro detects now; `--json` for scripts. `--suggest` prints the suggestion tables and the OpenCode provider it picked, `--save` writes the suggestions for every unset cell into the config (never overwriting yours), `set <harness>.<category> <model> [--effort E]` and `unset <harness>.<category>` edit one cell (indent 2, other keys kept), and `--check` compares the ids with the live models.dev catalog and reports missing, deprecated and newer-in-family models. The decision JSON has a new `model_source` key.
- Inside Codex, a delegation to a different model is `codex exec -m <model>`. OpenCode and Gemini CLI are subagent seats without any config, and `maestro install` writes their agent files with the resolved models. Jev candidate descriptions name the model (`"standard tier, Codex (gpt-6.1-sol) headless CLI, ..."`), and a model that serves two categories gets an `@<category>` suffix on the higher one.
- `detect` no longer reads `~/.codex/config.toml` / `~/.gemini/settings.json` (the inventory has no `default_models`); `catalog.json` keeps family, release date, status and tool support per model. `$MAESTRO_CATALOG_URL` overrides the catalog URL.
- **`mine.py harvest` keeps only prompts you typed.** Sessions started by a program (`claude -p`, the Agent SDK, an orchestrator dispatching Claude Code sessions, `codex exec`) are skipped and reported with their top projects; `--include-automated` keeps them. New `--project` / `--exclude-project` filters and a by-project summary. `--include-subagents` is documented as AI-written prompts.
- **`mine.py route` routes each prompt as the harness it came from** (Codex prompts as Codex, and so on) instead of always as Claude Code, and reports counts by harness and by model, plus a note when no local or network models are configured.
- **`evals/mine.py`: test Maestro on your own prompts.** `harvest` reads the prompt history of Claude Code, Codex, Gemini CLI and OpenCode (or a copied home directory from another machine with `--home`, or a blank-line-separated text file with `--from-file` for Cursor, aider and the rest), filters noise, dedupes, redacts likely secrets and samples. `route` runs the rules classifier with your real inventory and config and writes a CSV to review; `score` turns your corrections into job and category accuracy, under-routing and confusions, and `--export` writes them in the `evals/prompts.jsonl` format. Stdlib only, entirely local, and it leaves `maestro.py` untouched.

## 2.1.0

Plain-English jobs, six model categories, and local and network models.

- **Jobs replace task classes.** Eleven plain verbs: `plan`, `code`, `debug`, `review`, `ops`, `research`, `data`, `write`, `edit`, `summarize`, `ask` (the old `planning`, `coding`, `agentic`, `research`, `basic_work`, `extraction` and `chat` are gone). New keyword tables and difficulty priors for each. Difficulty is still 0 to 3.
- **Six categories replace the four tiers.** `local`, `fast`, `standard`, `strong`, `frontier` and `specialist`, described provider-neutrally. New default ladder with `local` cells for `ask`, `summarize` and `edit` at d0. Cloud order stays `fast < standard < strong < frontier`.
- **Decision JSON:** `task_class` is now `job` and `tier` is now `category` (no alias). Config `class_seats` is now `job_seats`.
- **Local and network models.** `maestro detect` probes Ollama, LM Studio, vLLM, SGLang and llama.cpp on localhost, `OLLAMA_HOST`, and the config's `local_endpoints` (URLs or `{name, url, kind, api_key_env}`), in parallel and in under 2 s. `maestro detect --scan [--save]` (opt-in, bounded, `MAESTRO_NO_SCAN` respected) finds servers on the local /24. Models are rated (`serves`) from their size, overridable with `local_models`, and chosen for the jobs that need no repo tools when `prefer_local` is on. Specialists (`specialists` config, or coder, sql and math model names) win for their jobs.
- **`maestro run <model-id> "<task>"`** sends one chat completion to a local or network model (Ollama or OpenAI-compatible) and prints the reply. The new `local` delegate replaces the `ollama` delegate.
- Codex, Gemini CLI and OpenCode can map every category through `harness_models`; a `harness_models` entry that names a detected local model runs it as a tools-capable subagent.
- Jev is asked a `job` question over the eleven jobs, and its candidates include local models and specialists with descriptions.
- `maestro_model.json` records the job list it was trained on and is ignored (heuristics only) when it does not match, so the v2.0 weights are not used with the new jobs. `evals/train.py` trains on `job` labels. `evals/run.py` reports `job_accuracy`, `category_accuracy` and `category_within_1`.
- Inventory format version 2 (`local_endpoints`, `local_models`); the Jev cache format is version 2. Local traffic bypasses HTTP proxies.

- **Classifier retrained on the 11 jobs.** `evals/prompts.jsonl` (474 prompts) and `evals/train.jsonl` are relabeled with the jobs; `maestro_model.json` is retrained (136 KB) and now also stores how hard each job usually is. Difficulty is scored per job, the jobs that need repo tools win a tie with a chat-only job (so repo work is not sent to a local model without tools), and the keyword tables were tuned for debug, edit and code-versus-summarize. Held-out test half: job accuracy 79.7%, category accuracy 53.2%, within one step 93.7%, under-routed 8.9%, severely under-routed 0.0%. CI thresholds are set from these numbers.

Also shipped in 2.1.0 (previously unreleased):

- Offline classifier: keyword rules now score the instruction only (fenced code and logs are material, not intent), with new signals for small edits, pasted-material extraction, agentic and research verbs; plus an embedded Naive Bayes model (`maestro_model.json`, trained by `evals/train.py` on `evals/train.jsonl`) that predicts class and difficulty and chooses the tier with least expected under-routing. Held-out half of the 350-prompt set: tier accuracy 48.6% -> 60.6%, under-routed 25.7% -> 8.6%, severely under-routed 6.9% -> 0%.
- `evals/run.py`: `--split dev|test|all`, tier within +-1, under-routed and severely under-routed metrics and gates, `--variant`. CI gates the test split.
- `pip install` ships the model to `<prefix>/share/maestro/`. `_FILE_RE` no longer backtracks quadratically on very long tokens.

## 2.0.0

A ground-up rewrite. Maestro is now a lean model router packaged as an Agent Skill and a Claude Code plugin.

- Single-file, stdlib-only router (`skills/maestro/scripts/maestro.py`, Python >= 3.9) with `route`, `detect`, `install`, `doctor` and `config`.
- Offline rules classifier (task class, difficulty 0-3, confidence, needs), plus a Jev (TypeSafe) classifier that picks the model directly from your eligible candidates (used automatically when `TYPESAFE_API_KEY` is set; rules fallback and a local cache).
- Policy ladder mapping class and difficulty to a tier (`fast`, `standard`, `strong`, `frontier`), with confidence escalation and a `max_tier` cap.
- Inventory of harness CLIs, subscriptions, API keys, Ollama models and hardware; routing never picks a seat you cannot run.
- Delegation as subagent, CLI, Ollama or inline, plus `maestro install` for OpenCode and Gemini CLI tier subagents.
- Eval set and scorer (`evals/run.py`), stdlib unit tests and CI on Python 3.9-3.13.
- Removed the earlier multi-service platform (services, Redis, Quorum, Vega, fleet, dashboard); Maestro is now a single stdlib package.
