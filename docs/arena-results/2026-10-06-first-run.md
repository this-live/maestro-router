# Arena: first run on a DGX Spark (2026-10-06)

The first end-to-end arena run on real hardware: the runbook (`docs/ARENA-RUNBOOK.md`) followed on two machines, a Mac
(where setup, the harness checks and a first attempt ran) and a DGX Spark (where the run below ran, harnesses and agentic
cells included). Only each seat's model call left the box; the Spark's model was reached over localhost.

Every number here is from 10 verifiable, 3-5 agentic and 5 open tasks. **The 95% intervals are wide; read them, not the
point estimates.** The answers, diffs and prompts stay on the machine that ran them; this page has aggregates only.

### Value frontier and routing replay

- **Value frontier**, all three suites: `claude-code:sonnet` is both the best seat and the cheapest seat whose interval
  reaches the best rate. The local Spark model is the $0 Pareto point (60% verifiable, 40% agentic).
- **Routing replay** (Maestro's rules classifier + ladder, cheapest seat of the chosen category):

| suite | router | always sonnet | always haiku | hindsight best |
|---|---|---|---|---|
| verifiable | 90%, $0.0070/task | 100%, $0.0075 | 100%, $0.0189 | 100%, $0.0036 |
| agentic (3 tasks) | 100%, $0.058 | 100%, $0.058 | 100%, $0.093 | 100%, $0.014 |
| open | 80%, $0.0146 | 100%, $0.0169 | 20%, $0.0075 | 100%, $0.0138 |

  The router stays close to hindsight on cost. It loses success where it sends a task to the local model (verifiable)
  or to haiku (open): "always sonnet" was as cheap and more reliable on this sample.

## Harness bugs found and fixed (on branch `arena/harness-fixes`)

1. **Claude Code: `--safe-mode`.** On a customized install, plugins, skills, hooks and MCP servers made a one-line
   prompt about 390k tokens, so every cell failed ("Prompt is too long"). `--safe-mode` keeps the subscription login and
   the built-in tools and drops the customizations: about 3.7k tokens, $0.004.
2. **OpenCode: `PWD`.** OpenCode works in `$PWD`, not its real cwd, and inherited the directory the arena was started
   from. It edited the real fixture in the repository instead of its copy. Every CLI now runs with `PWD` set to its
   cell.
3. **Escape attribution.** With `--concurrency 2`, a fixture change failed every cell running at the time. Cells on the
   same fixture no longer overlap.
4. **OpenCode `--standalone`** (2.x starts a shared background service that keeps the first cell's config) and Claude
   Code `--safe-mode` are added only when the installed CLI's `--help` lists them. OpenCode's current release (1.18.34)
   rejects `--standalone`.
5. **Hermes: `-Q`** plus a parser that drops startup warning lines. Without these, a banner, a boxed answer, resume hints
   and a "tirith" warning were graded as the answer.
6. **Codex sandbox preflight.** Agentic Codex cells first run `codex sandbox ... -- true` once. If the sandbox cannot
   start, the cells are skipped with the reason, never run unsandboxed, and are redone on resume.
7. `mine.py harvest` reads Hermes sessions.

Each fix has a unit test, and each was run live on the machine where it failed.

## Caveats

- The dry-run cost estimate was about 2-3x low. It ignores each CLI's fixed per-call overhead (Codex: 14-26k input tokens
  of system prompt and skills per call; Claude Code with `--safe-mode`: about 4k).
- A cell killed at its timeout records almost no cost (Claude Code reports cost only at the end).
- Codex still loads the user's skills (about 21-26k tokens per call on a heavily customized machine); `--ignore-user-config`
  removes only part of it. This inflates Codex's cost, not its quality.
- Of the owner's real prompts, only 7 of 5,709 were self-contained enough for an open suite. Most real usage is steering
  an agent in context, which the agentic fixtures measure better.

## Second run (bigger, partial: stopped at the owner's request)

Same day, run id `spark-full`. Codex's agentic seat ran on the Mac, where its sandbox works, and its rows were merged
into the Spark run. The run was wrapped up after the free stages and Codex, so **Claude haiku and sonnet have no
